# 翻车案例库与标题台账

> 用途：把"哪条被否、为什么被否、哪条最终上量"沉淀成可增长的知识，供季度修订 `title-spec.md`。
> 原则：只记录真实发生过的否稿与采用，不补写猜测数据；没有数据的字段写"未记录"。

## 一、失败模式分类（出稿前先扫一遍）

| 编号 | 模式 | 判定信号 | 处置 |
| --- | --- | --- | --- |
| F1 | 编造剧情 | 出现简介没写的背叛方式、牢狱、死因、反派下场 | 删除该素材，按白名单五维改写 |
| F2 | 字数不足 | 低于 50 字，或 60 字线以下 | 补爽点或重写，不放宽 |
| F3 | 版本趋同 | 打乱后分不清属于哪个方案 | 换路线重写，见 `title-spec.md` §1.3 |
| F4 | 打脸泛化 | 「腸子悔青」「跪地求饒」单独使用、无画面 | 换成打脸四式 |
| F5 | 开场平铺 | 「曾遭…的他」「…的那天」式叙述开场 | 换钩子手法 |
| F6 | 简体混入 | 标题中出现任一简体字 | 全量转繁体后复查 |
| F7 | 主角本名 | 标题出现主角真名 | 换成身份/关系称呼 |
| F8 | 爽点平行 | 五六个爆点同级罗列，没有递进 | 重排递进链 |
| F9 | 画面违规 | 图里有文字、武器、儿童、血腥 | 不进 Stage 2，重做提示词 |
| F10 | 审核红线 | 绝对化用语（最/唯一/第一/非他莫屬）、收益承诺、迷信、群体对立 | 只改表达不改事实，按 `platform-rules.md` A 层替换 |

## 四、从台账到规范修订的触发条件

满足任一条即可启动下一版规范（v5）的讨论：

1. **同一格位连续 3 部剧被否** → 该格的定义或结构有问题，重写该格说明。
2. **同一失败模式占近 5 部剧否稿原因的一半以上** → 提升为硬规则，写进 `title-spec.md` §6 质检清单。
3. **某格平均评分 < 3.5（七维均分）** → 该格与当前剧种不匹配，考虑替换方案层。
4. **上线表现出现明显分层（同格位 CTR 相差 2 倍以上）** → 把高效表达写进钩子/打脸式示例。
