# 标题评分卡（候选池交付前的择优依据）

> 用途：在候选池交付给用户之前，给每条标题打分，用于（1）淘汰不合格稿、（2）在平铺列表里标出推荐项。
> 评分只用于**推荐**，不改变"用户按组各选 3 条"的门禁规则，Agent 不得代选。
> 本评分卡只评**标题文案**：画面内容（含动物完整性）不参与评分，由 `cover-spec.md` §四的 P0 否决 + 人工/VLM 复核把关。

## 一、七维评分（每项 0—5 分）

| 维度 | 检查点 |
| --- | --- |
| 第一眼 | 1 秒内是否有抓手？前 10 字能否定住人？ |
| 与我有关 | 是否点中短剧受众的人群、处境或情绪？ |
| 信息缺口 | 是否让人必须点开才能闭环？ |
| 情绪峰值 | 是否有痛、痒、爽、惊、暖中的一种，且推到峰值？ |
| 具体画面 | 是否有可拍成镜头的动作、物件、数字或场景？ |
| 新鲜程度 | 是否不像又一条同赛道模板标题？ |
| 内容兑现 | 简介是否撑得住最亮的那个词？ |

## 二、硬门槛（先过线，再看总分）

- **内容兑现 < 4 → 直接重写**，不管总分多高。这一项对应 `title-spec.md` §2 素材边界，是防编造的最后一道闸。
- **具体画面 < 3 → 重写**，说明爽点停在概念层，没有落到画面。
- 其余维度不设单条门槛，避免机械砍掉有潜力的稿。

## 三、矩阵标注规则

在每个候选层的 12 条平铺列表中，逐条给出分数并标出推荐项：

- **上屏格式（硬约束）**：每条必须当场上屏七维分项（`5/4/3/5/4/3/5`）+ 合计 + 均值（两位小数）+ 推荐标注，呈现表格见 `title-spec.md` §10；只给推荐不给分数＝不合格；
- T 策划层每个版本（版1/2/3/4）各自 3 条方案中，总分最高者标 `推荐`，共 4 个推荐；N 投放层按四标准各取 3 条中的最高分，共 4 个（心理学三维度在标准 2/3/4 内，不另设推荐位）；
- 版4 同分时先比较「机制族是否与前三个版本明显不同」，再看内容兑现；
- 总分相同则比较"内容兑现 → 信息缺口 → 情绪峰值"的顺序，仍然同分则并列标注，由用户判断；
- 全表只标推荐，不排序、不删条；全部候选条（12 条或 24 条）都必须完整呈现。

## 四、推荐理由写法

每个推荐格附一句不超过 30 字的理由，必须落在具体维度上，例如：

- `推荐：兑现最稳，爽点链条完整，打脸落到资产对比`
- `推荐：信息缺口最大，开场用身份歧视反问，前 10 字即冲突`

禁止写"更有爆款感""更抓人"这类无法验证的理由。

## 五、落选稿去向

- 用户未选中的候选条不丢弃，写进 `failure-cases.md` 的台账草稿（剧名 + 标题 + 未选原因由用户填写或留空），用于季度复盘；
- 连续在多部剧被同一原因否掉的格子，按 `failure-cases.md` §4 的升级规则处理。
