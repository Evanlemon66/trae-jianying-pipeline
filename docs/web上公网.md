# 交接：本地 Console 升级为「外网可用的在线 Web」（方案 A）

## 0. 一句话目标

让用户在外网用**手机浏览器**打开本机运行的剪映工作流 Console，查看状态、提交剪辑任务、跑环境检查。执行引擎仍留在本机 Windows。

## 1. 项目位置与技术现状

- 仓库根：`d:\剪映5.9\剪映5.9版+jianying-skill\国内用户下载这个（trae+skill）\trae-jianying-skill`
- Console 后端：`pipeline_ui/console/app.py`，**Python 标准库 `http.server`**，手写路由（`/api/*`），**零第三方依赖**，默认只听 `127.0.0.1:8765`，启动命令 `python pipeline_ui/console/app.py --port 8765`。
- 前端：`pipeline_ui/console/static/`，原生 JS 单页（`index.html` / `style.css` / `api.js` / `dialog.js` / `view.js` / `env.js` / `app.js`），按文件挂载 `window.API / View / Env / Dialog`。
- 页面：任务（`page-run`）、环境初始化（`page-env`）、归档清理（`page-archive`）、历史（`page-history`）。
- 执行链：`pipeline_ui/console/runner.py` 起子进程跑 `pipeline/batch_runner.py`；记录写 `pipeline_ui/_console/runs.jsonl`；导出有全局文件锁（`export_lock`）；watcher 通过 Windows 计划任务拉起。
- 已有能力（上一轮刚做）：`POST /api/run/export-only` + `Runner.export_only()`（对已存在草稿只做导出，`mode=export_only`），历史页有「类型」列（仅剪辑 / 剪辑+导出 / 仅导出）。
- 测试基线：`python -m pytest tests -q` → **452 passed**。

## 2. 硬约束（决定方案边界）

| 约束                       | 含义                                      |
| :----------------------- | :-------------------------------------- |
| 剪映桌面版 + UI 自动化           | 导出靠截图/图像识别点剪映界面，**无法搬到无头云环境**           |
| Windows 交互式桌面            | 锁屏 / 息屏 / RDP 断开 → 导出失败（建稿不受影响）         |
| 本机 GPU / CUDA / OCR / 模型 | 环境检查与部分链路依赖真机                           |
| 本地文件系统                   | 素材根、导出根、草稿索引、归档都按本机路径                   |
| 当前无鉴权                    | 一旦暴露公网 = 把 `deps.install`、归档执行、提交任务全交出去 |

## 3. 四个方案与结论

| 方案                  | 说明                                                    | 结论              |
| :------------------ | :---------------------------------------------------- | :-------------- |
| **A. 隧道直连**         | Cloudflare Tunnel / Tailscale 把 `127.0.0.1:8765` 映射出去 | **已选定**，满足手机远程用 |
| B. 云端控制面 + 本地 Agent | 云端 Web+DB+队列，本机 Agent 出站拉任务                           | 长期方向，现在不做       |
| C. 前端上云 + 本地 API    | 静态托管 + CORS                                           | 收益低，不做          |
| D. 全云化执行            | 云 Windows GPU + 剪映，或无头重写剪辑链                           | 成本高/需重写，不做      |

## 4. 成本

- Cloudflare Tunnel / Access：**免费**（Access 免费版 ≤50 用户，邮箱 OTP 登录）
- 域名：**¥60–100/年**（命名隧道需要；Tailscale 方案不需要）
- 服务器/VPS：**0**
- 通知（飞书/Telegram webhook）：**免费**
- 真实持续成本 = **电费**：机器常开约 **¥40–80/月**（100–150W）

## 5. 工作量拆解（粗估，非承诺工期）

| 工作项                             | 改动位置                                        | 量级         |
| :------------------------------ | :------------------------------------------ | :--------- |
| 隧道 + Access 接入                  | 纯配置，0 代码                                    | 小          |
| 应用层鉴权 + CSRF + Origin 校验 + 失败限流 | `app.py` 统一请求入口、`static/api.js`、极简登录页       | 中          |
| 移动端响应式                          | `style.css` + `app.js` 抽屉 + `view.js` 表格卡片化 | **大（最大头）** |
| 任务完成 webhook 通知                 | `runner.py` 收尾处 + 配置项                       | 小          |
| 成片下载/在线预览                       | 新增只读路由 + 路径白名单                              | 小          |

- MVP（隧道 + 鉴权）：**半天到 1 天量级**
- 完整可用版（含移动端适配 + 通知 + 下载）：**约 3 个开发日量级**
- 真正耗时在手机真机调断点与触控

## 6. 用户待确认的 4 件事

1. **隧道选哪个**：Cloudflare（要域名、不装 App、可临时分享）还是 Tailscale（不要域名、要装 App、仅自己设备）？
2. **有没有可用域名**（Cloudflare 命名隧道需要）？
3. **会不会分享给别人临时用**（决定鉴权强度）？
4. **手机是否要看/下载成片**（决定是否做成片下载路由）？

## 7. 实施顺序（建议）

1. 接隧道 + Access，桌面浏览器先在外网验证通不通（不改代码）
2. 补应用层鉴权 + CSRF + Origin 校验（**不做这步就别开公网**）
3. 移动端响应式（侧边栏抽屉 / 任务页单列 / 历史与归档表格卡片化 / 触控区 ≥40px）
4. 任务完成 webhook 通知
5. （按需）成片下载或在线播放

## 8. 移动端适配的具体落点（已核实的现状）

- `.sidebar` 固定 `236px`，手机 390px 宽时正文只剩 \~150px → 改顶部抽屉或底部 Tab
- `.run-grid` 为 `minmax(0,1fr) 404px` 两栏 → ≤760px 改单列，右栏状态卡折叠成页首摘要
- 历史表已有 10 列（运行ID/开始/链路/类型/剧·草稿/状态/结论/阶段/退出码/操作）→ 窄屏改卡片列表
- 现有断点：`1120px`（run-aside 取消 sticky）、`1199px`、`760px`；缺真正的手机断点
- 状态栏 `.statusbar` 可点击项（`sb-link`）在手机上应精简为「服务 / 当前任务」

## 9. 安全必做项（当前完全缺失）

- 现在**没有任何鉴权、没有 CSRF token、没有 Origin 校验**，仅靠只监听 127.0.0.1
- 必须：token 或 Cookie 会话（所有写接口校验）、POST 带 CSRF token 并校验 `Origin`/`Host`、失败限流、操作审计日志
- 顺带要堵：`/api/runs/<id>/rerun` 与归档 `draft` 参数做白名单/路径校验；日志中本机绝对路径脱敏

## 10. 手机能做什么 / 不能做什么

| 场景              | 可否 | 备注               |
| :-------------- | :- | :--------------- |
| 看服务/任务/导出锁状态    | ✅  | 现有轮询过隧道可用        |
| 选剧集、提交「仅剪辑」任务   | ✅  | 只能选本机已有剧集目录      |
| 看进度与日志          | ✅  | 建议手机端压缩刷新频率      |
| 完整环境检查          | ✅  | 耗时长，注意手机息屏       |
| 归档 dry-run / 执行 | ✅  | 需二次确认（已有 Dialog） |
| 对已有草稿「仅导出」      | ⚠️ | 需桌面保持解锁          |
| 上传新素材           | ❌  | 无上传接口            |
| 下载成片到手机         | ❌  | 需新增只读下载路由        |

## 11. 关键坑（务必写进实现）

1. **锁屏即导出失败**：远程主路径应是「仅剪辑出入草稿，回家再点仅导出」，不要依赖长期不锁屏跑自动导出。
2. 电脑必须常开且不休眠；建议自动登录 + 关闭锁屏；可选 BIOS 来电自启。
3. 手机提交任务用的仍是**本机路径**，不是上传文件。
4. 桌面 Toast 通知手机收不到，需要 webhook 出口。
5. 改 Python 后必须 kill 占用 8765 的 python 进程再重启；前端改动浏览器要带 `?v=` 强刷。

## 12. 验收标准

1. 手机 4G 打开 `https://<域名>` → 要求登录 → 能提交一个「仅剪辑」任务
2. 手机上能看到进度；锁屏解锁后仍可刷新
3. 未登录访问任何 `/api/*` 返回 401
4. 本机 `http://127.0.0.1:8765` 行为不变
5. （若做了通知）任务结束手机收到 webhook

## 13. 明确不做（避免新会话误解）

- 不做云控制面 / 多租户 / 任务队列上云（方案 B）
- 不重写剪辑/导出链路为无头渲染（方案 D）
- 不引入框架重写后端（仍保持零依赖 `http.server`，只在入口加鉴权与校验）
- 不做素材上传
