# 剪映 UI 自动化：分阶段采集与"隐藏台账"方案

- 状态：**待评审（未实施）**
- 适用范围：`pipeline_ui/` 下的轨道扫描、识别翻译、分离音频、最终布局落盘
- 结论口径：文中每一条都标注 `【已证实】`（有日志/实测/代码依据）、`【推断】`（由现有证据推出但未直接观测）、`【待实测】`（必须做实验才能定）。**不要把推断当结论使用。**

---

## 1. 背景与要解决的问题

当前流水线对"时间线轨道"的所有判断，都建立在一个隐含前提上：**每一刻扫到的行 = 当前存在的全部轨道**。这个前提在真实操作中不成立，由此产生三个已发生的故障。

### 1.1 问题一：隐藏轨会从扫描结果里"消失"

`scan_tracks()` 依赖 `detect_track_rows()` 的亮度带扫描：行内必须有足够亮的片段像素才会被识别成一条轨。
一旦某条轨被隐藏，行内像素变空，行要么被判成 `type=unknown`，要么直接不出现。

`【已证实】` 2026-11-14 02:27 准入日志：
- `[1/6] 隐藏并锁定两条字幕轨` → 隐藏 988 → 946；
- 之后 `[reuse] 复用上一阶段轨道扫描（3 行）`；
- `字幕轨簇只有 0 条`。

即：两条字幕轨隐藏后，完整扫描里再也找不到它们（或找到也无法判定类型），后续"恢复"无对象可点。

### 1.2 问题二：轨道是在操作之后才生成的，采集时机必须跟着阶段走

`【已证实】`
- 识别 + 翻译：`texts 0→600`，时间线新增 **2 条 text 轨**（中文 + 英文），不是 1 条；
- 分离音频：主轨下方新增 **1 条 audio 轨**，且整摞轨道会上移（实测主轨 `ymid 1282 → 1030`，上移 252 px）。

所以"启动时扫一次、后面一直用"必然错。轨道集合是**四个稳定态**，不是全程一个态。

### 1.3 问题三：恢复流程会"假绿"

`restore_all_tracks(win, scan_hint=hint)` 的实现是：

```
rows = scan_hint if scan_hint is not None else scan_tracks(win)
hidden = [r['ymid'] for r in rows if r['hidden']]
```

它**只在传入的 hint 里找隐藏行**。而 `ui_extract_audio.py` 传进来的 hint 是"分离音频成功后那一帧的 3 行"（主轨 + 音频 + 一条其他），根本不含被隐藏的 946/988。

`【已证实】` 结果是：恢复函数返回 `ok=True`、`clean_confirmed=True`，但两条字幕轨仍然是隐藏状态 → 后续"从上到下第二条字幕轨"直接算错，落到 `subs2` 为空、跳过终态隐藏。

### 1.4 问题四（矛盾点）：隐藏是 `Ctrl+A` 的前置条件，但"每 phase 全可见"不允许隐藏

`Ctrl+A` 是"全选时间线所有片段"。要让 `Ctrl+Shift+S` 只分离主轨，必须先让字幕轨不可见。

这与"每个 phase 开始/结束都以全可见为基线"直接冲突。本方案的核心就是把这条冲突解开：

> **隐藏不是信息丢失，而是"从可见集合移除 + 记台账"。**
> 可见集合可以随时变，但只要台账在、且 phase 边界能闭合，状态就是可预期的。

## 3. 分阶段采集（4 段 phase）

### 3.1 总表

| Phase | 触发时机 | 可见行数（锁图标口径） | 文件 `tracks` | 新增 | 结束态 |
|---|---|---|---|---|---|
| **P0 基线** | 进入编辑页、任何操作前 | 5 | 8【已证实】 | — | 全可见 |
| **P1 字幕落地** | 识别 + 翻译完成 | 7 | 8 | +2 text | 全可见 |
| **P2 音频分离** | `Ctrl+Shift+S` 完成 | 8 | 8 | +1 audio | 全可见（隐藏的 2 条已恢复） |
| **P3 终态** | 只隐藏中文字幕轨 | 8（其中 1 条 hidden） | 8 | 0 | 1 条 `terminal_state` |

### 3.2 每个 phase 的四段动作

统一模板：**采集 → 规划 → 执行 → 复核**。

#### P0 基线

- **采集**：完整 `scan_tracks`；统计可见行数；读取 `draft_content.json` 的 `tracks` 长度；记录主轨 `ymid`、眼睛列 `eye_x`、锁定列 `lock_x`。
- **规划**：确定主轨（最底部 video 行 + 封面按钮双重判定）；确认无遗留隐藏/锁定。
- **执行**：若存在非预期 hidden/locked，先走完整恢复（不依赖 hint）。
- **复核（phase 结束断言）**：
  - 可见行数 == 5【已证实可达】；
  - `hidden` 行数 == 0；
  - 主轨可定位；
  - 文件 `tracks` == 8（不一致时只告警，不阻断——见 §4）。

#### P1 字幕落地

- **采集**：完整扫描一次；筛 `type=='text'`；取顶部连续簇（阈值 60 px = 40 × `_HDR_SCALE`）；记录每行的眼睛/锁定坐标。
- **规划**：确认簇内恰好 2 条（中/英）；确认这两条都在最顶部、与下一条间距 > 60 px。
- **执行**：写入 `calibration.subtitle_tracks.tracks[]`。
- **复核（结束断言）**：
  - 可见行数 == 7；
  - text 行数 == 2 且成簇；
  - **记录条数 == 2**（当前代码只记录到 1 条，见 §9.3）。

#### P2 音频分离

- **采集**：分离成功后做一次**完整扫描**（不得复用只含 3 行的 hint）；
- **规划**：重新定位主轨（不能拿分离前的 `main0` 当参照——整摞会滚动）；取主轨下方最底行作为新 audio 轨。
- **执行**：`Ctrl+A` 前先隐藏两条字幕轨（走台账，见 §5）；`Ctrl+Shift+S`；等新行出现。
- **复核（结束断言）**：
  - 可见行数 == 8；
  - 主轨下方恰有 1 条 audio 行；
  - 台账内（除 terminal_state）全部 `restore_verified=True`；
  - 完整扫描里不存在"台账之外"的 hidden 行。

#### P3 终态

- **采集**：完整扫描 + 台账回放；
- **规划**：确定"从上到下第二条字幕轨"= 中文轨；
- **执行**：隐藏该行，写入台账并标 `reason=terminal_state`；
- **复核（结束断言）**：
  - 总行数 == 8；
  - hidden 行数 == 1 且与台账 `terminal_state` 条目一一对应；
  - 其余 7 行可见且未锁定；
  - `final_layout` 落盘 8 行（含 hidden 行的类型补正）。

### 3.3 phase 边界规则（替代"一直全可见"）

- **phase 开始**：台账必须为空（或只含 `terminal_state`），并做一次完整扫描作为基线；
- **phase 内**：允许临时隐藏，但每一条都必须能通过台账恢复；
- **phase 结束**：断言除 `terminal_state` 外台账全部闭合（`restore_verified=True`）。

这样"全可见基线"只在**边界**成立，不再约束 phase 内的中间步骤。

## 4. 轨道计数口径

| 口径 | 用途 | 局限 |
|---|---|---|
| **左锁图标计数** | 可见态分母（`is_row_hidden` / `is_row_locked` 的条带判定） | 只能数"当前可见"的行；隐藏行塌缩后数不到；锁定行仍算可见 |
| **文件 `tracks` 条数** | 轨道总数交叉校验 | 含空轨/无片段轨；与可见行不是一一对应（F7：8 vs 5） |
| **完整扫描行数** | 操作目标的实际定位 | 受视口裁切、隐藏、塌缩影响 |

**规则：**

1. **锁图标只能当可见态分母，不能当轨道总数。**
2. 文件 `tracks` 条数只做交叉校验：`可见数 <= tracks 数` 恒成立；不等时记录差集，不阻断流程。
3. 隐藏行的可观察性分两段：

| 阶段 | 能否被 `scan_tracks` 扫到 | `type` | 眼睛条带 | 可用于恢复的锚点 |
|---|---|---|---|---|
| 隐藏后、塌缩前 | 能【已证实】 | `unknown`（采不到片段像素） | 蓝（`>=8`） | `ymid` 有效，可点 |
| 塌缩后 | 不能【推断】 | — | — | `ymid` 失效，只能用台账回退 |

4. 因此"总轨道数"的唯一可信来源是**文件 `tracks` + 台账**，不是任何一次扫描。

## 5. 隐藏台账

### 5.1 结构

内存 list，持久化到 `ui_calibration.json` 的 `hidden_ledger`：

```json
{
  "hidden_ledger": {
    "schema": 1,
    "phase": "P2_extract_audio",
    "main_ymid_at_hide": 1030,
    "entries": [
      {
        "id": "L1",
        "label": "subtitle_zh",
        "type": "text",
        "reason": "ctrl_a_isolation",
        "ymid_at_hide": 946,
        "offset": 84,
        "row_index_at_hide": 5,
        "track_count_at_hide": 7,
        "eye": [78, 946],
        "hidden_at": "2026-11-14T03:57:12",
        "restored_at": null,
        "restore_verified": false
      }
    ]
  }
}
```

字段说明：

| 字段 | 含义 | 为什么需要 |
|---|---|---|
| `offset` | `主轨 ymid − 该轨 ymid` | 恢复主锚点；整摞平移时不变 |
| `ymid_at_hide` | 隐藏瞬间的绝对 y | 失败取证 / 与 offset 互校 |
| `row_index_at_hide` | 隐藏时该行在全部行中的序号 | 塌缩后 offset 失效时的回退锚点 |
| `track_count_at_hide` | 隐藏时的总行数 | 判断之后是否插入过新轨 |
| `reason` | `ctrl_a_isolation` / `separate_audio` / `terminal_state` | 决定是否参与"必须恢复"断言 |
| `restore_verified` | 点后复检是否确认变回显示 | phase 结束断言的依据 |

### 5.2 offset 不变式

定义：

```
offset = main_ymid − row_ymid          （主轨减该轨）
恢复： y_pred = main_now − offset
```

**为什么用这个方向**：主轨是唯一始终存在、且能稳定定位的锚点（`find_main_track` 双判定）；被隐藏的多为字幕轨，位置随整摞移动，用主轨做基准最稳。

### 5.3 写入时机（硬约束）

**必须先采集、再隐藏，一条一追加：**

1. 隐藏前扫描，拿到 `main_ymid` 与该行 `ymid`，算 `offset`；
2. 追加 entry 到内存台账，**立刻写盘**；
3. 调 `_set_row_hidden(..., want_hidden=True)`；
4. 成功后回写 `hidden_at`；失败则标 `failed` 并从待恢复集合剔除。

顺序不能反：隐藏后 `type` 退化、可能塌缩，信息就采不到了（这也是现在 `_write_final_layout` 要传 `type_overrides` 的原因）。

**每隐藏一条追加一条**，不允许"批量隐藏后统一记"——中间任何一条点击失败或位移，批量记录就全错。

### 5.4 恢复流程（完整扫描 / LIFO / 只点一次 / 点后复检 / 失败即停）

```
for entry in reversed(entries):                 # LIFO：后藏先恢复
    rows, img, ..., eye_x = scan_tracks(win)    # 必须完整扫描，禁止用 hint
    main_now = find_main_track(win, rows, img)
    y_pred = main_now.ymid - entry.offset

    # ① 位置合法性
    row = nearest_row(rows, y_pred)
    if row is None or abs(row.ymid - y_pred) > 6:
        STOP(entry, "y 预测与实测行不匹配", 截图+台账快照)

    # ② 状态合法性
    if not is_row_hidden(img, ..., row.ymid):
        if entry.restore_verified: continue      # 幂等
        STOP(entry, "该行状态与台账不符")

    # ③ 只点一次
    _set_row_hidden(win, eye_x, y_pred, False, entry.label)

    # ④ 点后复检：眼睛必须变回"显示"
    img2 = 重新截图
    if is_row_hidden(img2, ..., y_pred):
        STOP(entry, "点击后未变回显示", 截图)

    entry.restore_verified = True
```

要点：

- **失败即停**：不重试、不换坐标补点第二次。误点第二次会把"显示"点成"隐藏"，把可恢复错误变成不可恢复错误。
- 复检与隐藏判定用**同一套**判据（`eye_strip=[60,90]×scale`、`blue_threshold=8`），保证对称。
- 失败时落截图 + 台账快照，便于离线重算。
- 全部恢复后做**终态断言**：除 `terminal_state` 外全部 `restore_verified=True`，且完整扫描里没有"台账之外的 hidden 行"。

### 5.5 三种情况下 offset 是否不变

| 情况 | 是否不变 | 不变式 / 例外 |
|---|---|---|
| **滚动** | **不变**【已证实：主轨 1282→1030，字幕轨同步上移】 | 不变式 `Δmain == Δrow`。例外：① 任一行被视口裁切 → `detect_track_rows` 的 `a > TR_T + 30` 会把它过滤（F4）；② 亚像素滚动导致 ±1~2 px 抖动 → 容差 6 px 吸收；③ 横向缩放（时间轴 zoom）不影响 y。 |
| **插入新轨** | **看位置**：插在"隐藏行与主轨之外"（顶部加字幕、主轨下加音频）→ **不变**；插在"两者之间"→ **改变**，改变量 = 新轨高度 | 不变式 `offset_new = offset_old + Σ(插在两者之间的轨高)`。判断依据：`row_index_at_hide` 与 `track_count_at_hide`。真实两种插入（P1 顶部 +2 text、P2 主轨下 +1 audio）都不在中间，**当前安全**；一旦出现中间插入必须重算。 |
| **塌缩** | **可能失效** | 只要行"还在、只是变空"，offset 成立（F3）。若行真被收拢/移除，`y_pred` 会算错。判定：`y_pred ± 6 px` 内找不到任何行 → 判为塌缩，走回退：用 `row_index_at_hide` 从下往上重锚 + 眼睛列交叉确认；仍不成立就 STOP，**禁止按旧 offset 盲点**。 |

补充：隐藏/解锁**不引起行位移**（F9），所以同 phase 内"藏 A → 藏 B → 恢复 A → 恢复 B"不会互相干扰；真正动 y 的只有滚动、插入、塌缩三类。

## 6. 终态豁免（`terminal_state`）

- **定义**：P3 里"业务要求最终只保留英文轨，因此故意隐藏中文字幕轨"这一条，`reason=terminal_state`。
- **仍写入台账**：否则无法区分"故意隐藏"与"上轮遗留/异常隐藏"，下一轮会把它当脏状态乱恢复。
- **豁免规则**：
  1. 不参与"phase 结束台账必须清空"断言；
  2. 不参与恢复循环；
  3. 但参与"隐藏行总数 == 1"的终态校验；
  4. 下一轮 P0 若发现它仍隐藏，视为**合法初始态**，不报警。
- 除 `terminal_state` 外，**任何跨 phase 携带的隐藏都视为缺陷**，必须报错。

## 7. 需临时隐藏的操作清单

| 操作 | 为什么要藏 | 藏哪几条 | 同 phase 内必须恢复？ |
|---|---|---|---|
| **`Ctrl+A` 选主轨**（`ui_extract_audio.py` Step 1–2） | `Ctrl+A` 是全选，不藏字幕轨会连字幕一起选中 | 顶部成簇的两条 text 轨，**从下往上**依次隐藏（防位移错位） | **是**（Step 5 恢复，且必须在 Step 6 之前） |
| **分离音频**（`Ctrl+Shift+S`） | 依赖上一条的"只选中主轨" | 不额外隐藏 | **是**（与上条共用同一批台账条目，恢复一次即可） |
| **其它"只操作主轨"的批量操作**（后续可能加：主轨空白段删除、主轨整体变速） | 同 `Ctrl+A` 语义 | 同样的非主轨集合 | **是** |
| **锁定轨道**（`lock_track`） | 锁定不改变可见集合、不引起位移 | 0 条 | 不适用（建议同样进台账 `locks` 子表，便于复检） |
| **终态隐藏中文字幕轨** | 业务要求 | 1 条 text | **否**（`terminal_state`） |
| **识别/翻译后的坐标记录** | 不需要隐藏 | 0 条 | 不适用 |

规则一句话：**为隔离选区而隐藏的，必须同 phase 内按台账恢复；为业务终态而隐藏的，标 `terminal_state` 永久豁免。**

## 9. 未决议题

### 9.1 用"点选主轨片段"替代 `Ctrl+A`（长期）

- **动机**：若能直接点中主轨某个片段，就不需要隐藏任何轨，§7 的临时隐藏清单会大幅缩短。
- **阻碍（已观察）**：`Config/globalSetting` 中 `disable_qt_access=1`、`accessibleDisableUnignoredChildren=1`——剪映主动关闭了 Qt 无障碍桥。时间线又是自绘区域。
  → `【推断】` UIA 大概率枚举不到单个片段，只能看到窗口/面板级容器。
- **`【待实测】` 验证方法**：打印时间线区域 UIA 树的深度与节点数，检查是否存在 `ControlType=ListItem/Image` 且带 `BoundingRectangle` 的片段节点；同时统计节点数量是否随片段数变化。
- **若可行，如何确认"只选中主轨"**：无可靠 UIA 属性可读，只能用"该行命中主轨 + 片段出现选中描边（像素判定）"双重启发式。
- **代价**：需新增"片段级定位 + 选中态识别"模块，随版本/主题/缩放变化要重标定；收益（少两次点击）远小于成本。

### 9.2 右键主轨片段走菜单路径（中期，优先级高于 9.1）

- **动机**：右键某个片段 → "分离音频"，天然只作用于该片段，不需要全选、不需要隐藏。
- **`【待实测】` 可行性**：需要确认右键菜单里该项的位置/文案稳定，以及菜单是原生菜单还是自绘（自绘只能用图像/OCR 定位）。
- **代价**：只需"菜单项定位"，不涉及片段级 UIA 枚举，成本明显低于 9.1。
- **风险**：菜单项文案随版本变化；点错菜单项可能执行破坏性操作，必须有"菜单截图 → 目标项校验"再点击。

### 9.3 识别 + 翻译后只记录到 1 条坐标

- **事实**：日志 `已记录 1 条字幕轨图标坐标`，但实际新增 2 条（F1）。
- **`【待实测】` 两种可能**：
  1. **时机问题**：记录发生在第二条轨渲染完成之前（第二行还没出现在扫描里）；
  2. **簇分割问题**：两行间距被 60 px 阈值切开（4K@150% 下实测字幕行距 42 px，理论上应同簇）。
- **建议**：先加"等 2 条稳定 N 帧再记录"的重试（低成本）；若仍为 1 条，再查簇阈值。**不要**直接改阈值，否则会把"字幕轨簇"和"其它 text 轨"混在一起。

## 10. 已知风险与前置条件

1. **冷启动早退（P3）**：5.9 存在间歇性"3.1 s 静默退出 0"。
   - 【已证实】关闭 `enableAutoUpdate` / `totalSilentUpgradeSwitch` / `forceUp` 后仍可复现，且全程无 `update.exe`、无新增 `JianyingPro_Install_*.log`，因此**自动更新不是直接原因**。
   - 【已证实·相关】6 次冷启动里出现 2 次早退，两次都紧跟在"上一个实例被 `Stop-Process` 强杀"之后（先杀→下一次 3.1 s 退出→再下一次正常）；`ParfaitServer\lock\886\` 里能看到被杀实例留下的 `JianyingPro_<pid>` 锁文件。**相关性成立，因果未证**。
   - 【待实测】需要确认触发物是 Parfait 锁/ready 握手、托盘 IPC（`tray_detect_main_app_is_alive_using_ipc=true`、`tray_detection_timer_interval_in_seconds=4`）还是命名互斥量；失败实例自身也会留下同名锁文件，因此"锁文件存在"不能单独作为判据。
   - 对方案的影响：phase 断言假设"进程存活且进入编辑页"，仍需上游启动重试兜底；建议重试策略保留"死亡后立即再起一次"，不要一次性放大到多次。
2. **恢复误判的代价高于不恢复**：所以 §5.4 坚持"失败即停、禁止盲点第二次"。
3. **终态被误恢复**：`terminal_state` 必须持久化，否则下一轮 P0 会把中文轨重新展开，导致终态被破坏。
4. **视口裁切**：轨道多时上下边缘行会被 `detect_track_rows` 丢弃；断言里必须允许"可见行数 < tracks 数"，不能硬等 8。
